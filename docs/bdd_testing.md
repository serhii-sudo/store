# Store — Django Project

## BDD Testing

Для BDD-тестирования проекта используется Behave.

### Django Environment Configuration

Файл `environment.py` содержит настройки окружения Django для выполнения BDD-тестов.

| Компонент                  | Назначение                                                                                                       |
|----------------------------|------------------------------------------------------------------------------------------------------------------|
| `os.environ.setdefault()`  | Устанавливает переменную `DJANGO_SETTINGS_MODULE`, указывающую расположение настроек Django.                     |
| `django.setup()`           | Инициализирует Django и загружает приложения проекта.                                                            |
| `get_user_model()`         | Получает активную модель пользователя, определённую в `AUTH_USER_MODEL`.                                         |
| `setup_test_environment()` | Активирует дополнительные возможности тестового окружения Django, включая доступ к контексту шаблонов в ответах. |
| `Client`                   | Позволяет имитировать HTTP-запросы к приложению без запуска веб-сервера.                                         |
| `reverse()`                | Формирует URL на основании имени маршрута из `urls.py`.                                                          |
| `before_scenario()`        | Выполняется перед каждым сценарием Behave и создаёт тестовый HTTP-клиент.                                        |

### Behave components

| Компонент          | Назначение                                                   |
|--------------------|--------------------------------------------------------------|
| `@given`           | Описывает начальные условия сценария.                        |
| `@when`            | Описывает действие пользователя.                             |
| `@then`            | Описывает ожидаемый результат.                               |
| `@step`            | Универсальный декоратор для шага.                            |
| `Feature`          | Описывает тестируемую функциональность.                      |
| `Scenario`         | Описывает конкретный тестовый сценарий.                      |
| `Scenario Outline` | Позволяет выполнять один сценарий с разными наборами данных. |
| `Examples`         | Содержит наборы данных для `Scenario Outline`.               |
| `environment.py`   | Содержит хуки и настройки окружения Behave.                  |

### And не имеет собственного декоратора. Behave определяет его тип по предыдущему шагу

| Gherkin             | Декоратор Python               |
|---------------------|--------------------------------|
| `Given`             | `@given`                       |
| `When`              | `@when`                        |
| `Then`              | `@then`                        |
| `And` после `Given` | `@given`                       |
| `And` после `When`  | `@when`                        |
| `And` после `Then`  | `@then`                        |
| `But`               | Наследует тип предыдущего шага |

### Behavior of variables and context

| Компонент          | Назначение                                                     |
|--------------------|----------------------------------------------------------------|
| `context`          | Общий объект для хранения данных между шагами одного сценария. |
| `context.client`   | Хранит экземпляр Django Test Client.                           |
| `context.response` | Хранит HTTP-ответ от предыдущего запроса.                      |
| `context.user`     | Может хранить созданного тестового пользователя.               |
| `context.form`     | Может хранить Django-форму из ответа.                          |
| `context.text`     | Может хранить текст, переданный из `.feature`.                 |
| `context.table`    | Содержит таблицу данных из `.feature`.                         |
| `context.config`   | Содержит настройки Behave.                                     |
| `context.scenario` | Информация о текущем сценарии.                                 |

### Основных теги-метки BDD (Behave), которые удобно использовать для классификации сценариев.

| Тег           | Назначение                                                                       | Пример использования                 |
|---------------|----------------------------------------------------------------------------------|--------------------------------------|
| `@positive`   | Позитивный сценарий — проверка успешного выполнения                              | Успешная регистрация                 |
| `@negative`   | Негативный сценарий — проверка обработки ошибок                                  | Регистрация с существующим email     |
| `@smoke`      | Smoke-тестирование — проверка основных функций приложения                        | Успешная авторизация                 |
| `@regression` | Регрессионное тестирование — проверка, что старый функционал продолжает работать | Проверка регистрации после изменений |
| `@critical`   | Критически важный функционал                                                     | Авторизация пользователя             |
| `@validation` | Проверка валидации данных                                                        | Некорректный email                   |
| `@security`   | Проверка безопасности                                                            | CSRF-защита                          |
| `@api`        | Сценарии тестирования API                                                        | Проверка REST API                    |
| `@ui`         | Сценарии проверки пользовательского интерфейса                                   | Проверка отображения формы           |
| `@slow`       | Сценарии с длительным выполнением                                                | Проверка сложных процессов           |

### Command to run Behave

| Команда                                    | Назначение                                                                                  |
|--------------------------------------------|---------------------------------------------------------------------------------------------|
| `python -m behave`                         | Запускает все BDD-сценарии.                                                                 |
| `python -m behave --no-capture`            | Отключает перехват стандартного вывода (`stdout`), отображая сообщения `print()` в консоли. |
| `python -m behave --no-color`              | Отключает цветное форматирование вывода Behave.                                             |
| `python -m behave --no-color --no-capture` | Запускает тесты без цветного форматирования и перехвата вывода `print()`.                   |
| `python -m behave --name="Регистрация"`    | Запускает сценарии, название которых соответствует указанному выражению.                    |
| `python -m behave --tags=@registration`    | Запускает сценарии, соответствующие указанному тегу.                                        |
| `python -m behave -v`                      | Выводит дополнительную информацию о выполнении тестов.                                      |


### - wsgi_request — то, что Django получил от клиента.
### - context.response — то, что Django вернул клиенту.
### То есть через wsgi_request ты исследуешь входящий запрос, а через response — результат его обработки.

### Running BDD Tests

Для запуска BDD-тестов используется команда:

```bash
python -m behave

```
